Eval Harness — How It Works

Reproducible, dependency-light scoring for the offline assistant · retrieval and generation judged separately · 24 Sep 2026

1. The big idea

One question goes through a fixed 6-step pipeline. Retrieval (did we find the right note?) is scored even with no model running. Generation (is the answer honest and cited?) is scored only when a model response exists — never guessed. Every run ends in machine-checkable gates (pass/fail), so results are comparable across weeks.

2. Each step, plainly

StepWhat happensSafety property
ValidateSubject must exist, unit must belong to it, top_k 1–10, query non-empty.Bad input fails fast, never reaches the model.
ScopeSubject comes from the UI (trusted). Unit comes from the optional dropdown, else a classifier picks one only if confidence ≥ 0.80 — otherwise "ambiguous".Model never invents subjects or units.
RetrievePer-subject BM25 index (built once, cached, rebuilt on file change). Title ×3, headings ×2, body ×1. One widen-to-subject retry if the unit search is weak.Search is bounded to verified notes; paths are allow-listed.
GateThree signals: top score, margin over 2nd place, query-word coverage (≥ 0.60). Pass → answer. Weak → clarify. Very weak or out-of-domain → refuse.Refusal is structural, not begging the model to behave.
GenerateModel must return JSON: {status, answer, claims[{text, source_ids}]}. Max 1 model call, 30s wall budget. ExtractiveGenerator runs fully offline for testing.Free text is never shown; only validated claims render.
ValidateEvery claim's source_id must be in the retrieved set; word-overlap with the source must clear 20%; uncited claims fail. Failure → safe refusal text.Invented citations (N_fake_…) always fail.

3. Worked example (real run, offline)

Gold case dwdm-001: "What is the main purpose of a data warehouse?" → expects dwdm/unit-1/motivation-for-data-warehousing-and-data-mining.md.

validate_request (0.005ms) → resolve_scope (subject-wide, unit=None)
→ retrieve: 5 candidates, top = motivation-…md @ 11.29
→ evidence_gate: ANSWER (score ok, coverage ok)
→ generate (extractive, 1 model call)
→ validate_citations: 1 claim, source N_fef70442dc ∈ retrieved ✓
RESULT: status=answer, expected_rank=1, hit_at_1=true

Refusal path: "What is the capital of Mars?" → gate sees out-of-domain marker → REFUSE before any model call → "The verified notes do not cover this question."
Ambiguous path: "Tell me about patterns." → weak coverage → CLARIFY.
